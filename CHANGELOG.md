# Changelog

All notable changes to Blockiverse VR will be documented here.

The format is based on Keep a Changelog, and releases use tags cut from `main`.

## Unreleased

- Fixed material-aware block-break audio never firing for survival harvesting — the main way blocks are broken in the game. The cue resolves its material by reading the block at the target position, but survival command feedback is raised *after* the authoritative mutation has already replaced that cell with air, so it read air every time and fell through to the generic break sound. Creative editing was unaffected, because that path is driven by `CreativeInteractionController.BlockMutationApplied`, whose `BlockChange` carries the block that was removed. So the feature worked everywhere it was easy to notice and nowhere that mattered. The bridge now remembers what each removal took away, from `VoxelWorld.BlockChanged`, and consumes that when the break cue asks. Deliberately not read from the world's changed-block set, which collapses repeated edits to the *original terrain* block and would give a placed-then-broken cell the wrong material. Placement still reads the world, which is correct there — the new block is present by then — and on a client both orderings work: if the delta has landed the record answers, and if it has not the world still holds the old block.
- Fixed treading water anywhere in a deep column reading as wading. The first attempt at this only moved the flip point 11 cm: the guard was added to the wading branch but not to the fallback that ends the same function, and the fallback returns wading for exactly the case the guard had just excluded. It matters because the feet and body samples are 0.89 m apart, so the body clears the water line long before the feet do — for all but about one percent of vertical positions a player treading deep water reaches the fallback rather than the guard. Both now ask the same question. Known follow-up in #337: the sample reads the capsule's own column, and a character controller stays supported while overhanging a ledge by up to its radius, so standing at the lip of a submerged shelf still reads as treading.
- Fixed rising to the surface of deep water reading as wading. Wading was resolved by asking whether the water's surface cell was at or below the feet cell, which is true standing in a one-block puddle — and equally true floating at the top of an ocean, where the feet are in the topmost water cell and everything below them is more water. Calling that wading hands vertical motion back to gravity mid-swim, so the player sinks, re-enters the surfaced state, is buoyed back up, and oscillates at the water line instead of treading. The surface alone cannot separate the two cases; what does is the cell *below* the feet, which is ground in a puddle and water in an ocean. `FluidSubmersionState` now carries that sample, and wading requires it. Threaded through the head-hysteresis rebuild too, which reconstructs the state and would otherwise have quietly reverted to the old behaviour on that path.
- Fixed the underwater ambience staying silent after unmuting, and the lava ambience with it — the same never-retry shape was in both, and fixing one would have left an asymmetry nobody would remember was deliberate. Starting a loop is refused while its resolved volume is zero, so diving with Mute All on — or with the master or weather slider down — failed to start it. The loop is only ever requested when the swim state *changes*, so nothing retried: the player had to leave the water and get back in before unmuting had any effect. It now retries while submerged and silent.

- Fixed multiplayer join and leave notifications firing for the wrong seats and the wrong events. Both cues hung off Netcode's `OnClientConnectedCallback`/`OnClientDisconnectCallback`, which are documented as running "only on the server and on the local client" — so on a client seat they only ever name the local client, and every peer arrival and departure was filtered out by the bridge's own local-id guard. A joining player heard the world go quiet: nobody else ever seemed to arrive or leave. The same callbacks over-fire on the host, in two directions. A join that #330's compatibility gate *refuses* is disconnected by Netcode through the ordinary server disconnect path, so the host played the "player left" stinger and toast for someone who never joined — the more confusing because the refusal is exactly when a host wants to know nothing happened. And a host receives both a client event and a peer event for the same arrival, so the notification was raised twice. The session now tracks which peers it actually believes are present (`BlockiversePeerPresence`) and raises `ClientConnected`/`ClientDisconnected` only when that presence changes, sourced from Netcode's `OnConnectionEvent`, which is the one API that distinguishes the local seat from a remote peer. A refused connection was never present, so it cannot leave; a duplicate notification is the same arrival; the peers already in the world when you join are tracked silently so their eventual departure still registers; and ending your own session is one event rather than one departure per player still in the world. The raw callbacks keep driving the connection state machine, which was always correct.
- Stopped a host shutdown reading as everyone leaving. Tearing a session down disconnects each guest in turn and Netcode reports every one of them, so a host closing its own world announced a departure per guest — and because host save preparation runs before the shutdown, those could land well after the player asked to stop. Suppressing that on the host alone is only half of it: `OnClientDisconnectFromServer` also *broadcasts* each disconnect to the guests still connected, so in a three-or-more-player world every remaining guest was told the others left, a fraction of a second before losing its own connection. True message by message, wrong as a description — nobody left, the world closed. That one is only reachable now that client seats receive peer events at all, so the fix above introduced it; at the default of two players there is no second guest and it stays latent, but four are supported. A guest cannot tell the two cases apart at the instant Netcode reports them, because the only thing that distinguishes them — its own disconnect — has not arrived yet. So departures now wait out a short settle window and are withdrawn if this seat stops being in a live session, rather than being decided on the spot. Presence is tracked through teardown either way; only the announcement is withheld.
- Fixed a harvest answered after its timeout going through for free. #330 added a 5 s cap on how long a client waits for a survival command, which was right — without it a host that silently drops commands wedges the client at the pending cap for the session. But giving up on the reply also discarded the pending entry, and that entry is the only place the client holds the *position* the command referred to, so `HandleCommandResultMessage` could no longer raise `CommandFeedback` when the answer finally arrived. The host had already applied the harvest; the acting player got no block cue, no impact effect, no haptic — and because `SurvivalVitalsRuntime` charges harvest stamina from that same event, no stamina either. Client-local game state, not just presentation. The realistic trigger is not a host that went away (the transport's own 5 s disconnect timeout usually wins that race) but a reply stuck behind a paced snapshot burst. The timeout now frees the pending slot without erasing what the request was: expired descriptors move to a bounded retention store, oldest evicted first, so a late reply still resolves to its position and everything downstream of it still fires. `TimedOutCommandRequestCount` and the warning are unchanged; `LateCommandResultCount` makes the case observable instead of silent.

- Fixed torch shadows stepping along block edges instead of tracing what actually blocks the light. Put a Glowwick in a cave ceiling corner and its shadow had a hard, blocky edge that landed on 1 m boundaries — a stair-step rather than a silhouette. The cause was that punctual lights were being occluded **twice**. `AccumulatePunctual` already multiplies by the light's `shadowAttenuation`, a real cube shadow map that resolves occlusion to about 4 cm at five metres; the shader then multiplied the whole summed punctual total by the baked `emitterReach` gate as well. That gate is one line-of-sight sample per face — `VoxelLightSampler.SampleEmitterReach` returns exactly 0 or 1 and `ChunkMeshBuilder` writes the one value to all four vertices — so it resolves occlusion at 1 m, twenty-five times coarser, and wherever it was 0 it annihilated the shadow map's careful silhouette across the entire face. The two systems were not disagreeing so much as being composed by multiplication, where the worse one always wins. Each light now gets exactly **one** occlusion term, chosen by whether it owns a shadow slice: the nearest emitter (the only one `GlowwickLightManager.MaxShadowCastingLights` lets cast) is occluded by its shadow map alone, and every other emitter by the baked gate alone, which is still the only thing standing between a torch and the far side of a wall — URP punctual attenuation is otherwise pure inverse-square with no occlusion at all. Past URP's additional-shadow fade the cube map stops answering, so occlusion hands back to the bake rather than letting distance reopen the bleed-through. Emitter `shadowStrength` went from 0.7 to 1.0: it had been tuned while the bake was *also* hard-zeroing the punctual term, so it never actually governed anything, and 1.0 is what keeps "no light through walls" true now that the shadow map owns that job by itself. Costs nothing on the chunk rebuild path — no new rays, and `ChunkMeshBuilder` and `VoxelLightSampler` are untouched, so the existing line-of-sight tests still pin the bake's exact previous behaviour. Two things were deliberately *not* done: grading the baked value instead of leaving it binary would not have helped, because one value written to four vertices interpolates to a constant and adjacent faces still meet in a hard block-aligned seam — it turns a binary staircase into a banded one; and sampling the bake per corner, which would genuinely soften the edge, costs up to sixteen line-of-sight walks per face on the main-thread rebuild, which is the wrong side of the machine to spend on when the shadow map already resolves this correctly for the light that matters. Emitters without a shadow map keep the block-aligned edge.
- Gave swimming and water a voice. Swimming landed silent: entering the water, going under, and stroking through it made no sound at all. Water audio now hangs off `BlockiverseSwimProvider`'s state machine — the only authoritative submersion state on the rig — via a new `StateChanged` event, rather than a second system re-deriving "am I wet" from the world and disagreeing with the first. Entry splashes on the `Dry`/`Wading` to `Surfaced`/`Swimming` transition with volume scaled by descent speed through the `volumeScale` the thunder work added, so stepping off a bank and falling from height are audibly different events. The submerged loop holds open for a short release window after the head clears, because `SwimState` samples the head cell raw while `BlockiverseWaterView` applies its own hysteresis — without the dwell, treading water at the surface destroyed and recreated the loop's AudioSource every frame and clicked instead of playing. Strokes fire at 1.5 s while the swim provider owns vertical motion and the player is genuinely travelling — a swimmer held against a wall or sinking passively is not stroking. Wading deliberately does not splash: shallow water is already covered by the Water footstep bank, and a splash there would fire on top of every step at the water's edge. Emberflow is excluded throughout; lava is not water and must not sound like it.
- Fixed the landing cue never firing, and footsteps running in mid-air. The swim provider installed `GroundedOverride = () => !IsSwimming` permanently, and `BlockiverseGaitCycle.ResolveGrounded` *replaces* its ground probe when an override is set rather than combining with it — so the rig reported "grounded" on every dry frame, including free fall. That zeroed the tracked fall speed each frame (no landing cue could reach its 3 m/s threshold) and kept the step cycle running while falling, so footsteps and the head bob played in mid-air. The override is now installed only while swimming and cleared otherwise, handing the probe back.
- Corrected several ruleset cue lengths that had been carried over from the synthesized era rather than measured: `thunder_near` (0.90s claimed, 3.20s actual), `thunder_far` (1.10s vs 3.60s), and `snow_wind_loop` (15–30s vs 6.00s). Added the real bed-length rule, and the Classic Block Sounds toggle the settings list had omitted.
- Gave `emberflow_loop` a producer. The cue and its asset shipped in the audio pass but nothing ever played them; standing in lava is no longer silent, and the water cues stay suppressed for it.
- Retired the placeholder fluid-entry hook the audio pass had added to `SurvivalVitalsRuntime`. It existed only because no swim state machine had landed yet; with one in place it would have splashed a second time on every entry. The fall-breaking-into-water logic it sat next to is untouched.
- Gave the day/night cycle a sky it actually owns, and put clouds in it. Night rendered a full daylight sky with a bright horizon band behind a correctly dark world, and no weather state ever changed anything overhead. Both had one cause: the project shipped Unity's stock procedural skybox, whose only scene input is the *direction* of `RenderSettings.sun` — and Blockiverse uses one shared directional light for both sun and moon, rotated to come from overhead at night so the ground stays lit. That skybox saw a light above the horizon at midnight and dutifully drew noon. Nothing in the project ever wrote `RenderSettings.skybox` or any skybox property, so the sky had no idea what time it was. (The tan band at the horizon was that same skybox's stock ground colour, not fog — clear weather disables fog outright, and URP does not fog the skybox anyway.) The replacement is a generated material driven from the same `LateUpdate` that already owns the sun, ambient and fog, with elevation taken from the **clock** rather than the light's rotation — the whole point, since that light lies about elevation at night by design. Day/twilight/night gradient with a warm horizon at dawn and dusk, moonless nights darker than full-moon ones, and the sun disk hidden once the real sun is down, which also removes the stock skybox's odd sun-at-the-zenith at midnight. `CloudCoverage` finally renders: it had exactly one consumer, a lighting penalty, so "cloudy" only ever dimmed the world. Coverage now drives a noise *threshold* rather than an opacity, so low coverage gives a few small clouds that grow and join up as it rises — fading a full-sky sheet in and out reads as haze, not weather. Cloud noise is generated in the shader rather than sampled from a texture, so no new art asset ships.
- Made rain and snow something you can actually see. Cycling through every weather state changed the audio and the brightness and nothing else. The particles were there — they were impossible to see, for two compounding reasons. They were roughly **two hundred times too sparse**: precipitation came through the same one-shot burst pool the block-break puffs use, two particles every 0.6 seconds for rain, 4.5 cm across, 0.35 s long. Measured against those constants that is 1.17 raindrops on screen on average, subtending about 0.7°, with the view completely empty of rain 42% of the time; the ruleset asks for 150–250. Snow was worse in a funny way — it had no case in the count switch and fell through to the default of 4, so a blizzard drew twice as many particles as a thunderstorm. And **nothing fell**: the pool never set simulation space, so every particle inherited Unity's Local default, and the pool sits on the XR origin — the transform teleport, continuous move and snap turn all drive. "Rain" was welded to the player, drifted sideways at 0.25 m/s along the default cone's local +Z, and swung 45° with every snap turn. That also explains the flicker people saw in the corner of their eye: 72% of bursts spawned outside the forward view and died 0.35 s later, so turning your head caught the tail of one just before it vanished — the same bug, not a second one. Replaced with a continuous head-locked volume in **world** simulation space, so drops fall past you instead of travelling with you, and the box follows the head in position only so a snap turn no longer swings the weather. Rain renders as a stretched streak, snow as a drifting billboard, and density scales with the weather service's intensity and ramps over a couple of seconds so a front arrives rather than a switch being thrown.
- Fixed fog being stripped out of the Quest build entirely. Fog worked in the editor and did nothing in the APK, which is why cycling to Fog weather changed only the audio and the brightness. `GraphicsSettings` had fog stripping on Automatic, which keeps fog shader variants only if a scene **in the build** has fog enabled **at build time** — and both build scenes ship with fog off, because the lighting controller is the only writer and turns it on at *runtime*. So every fog variant was stripped, and the three `m_FogKeep*` flags sitting at `1` right underneath were ignored, which is what makes this look correct at a glance. This also restores underwater fog, which had the same fate: the values were always right (~5 m visibility in freshwater, forced on regardless of weather) and simply never reached the device.
- Added rising bubbles underwater, and made the water surface visible from below. Being submerged had fog and a camera-clear swap and nothing else, so going under read as "the screen went blue" rather than as being in water. Bubbles establish which way is up and only exist while you are actually under, driven off the submersion blend so they fade in with the rest of the underwater treatment instead of snapping on at the waterline. Looking up used to show a hole in the world: the surface quad was always there, but every fluid quad winds outward and same-family interior faces are merged away, so from underneath it was back-facing and culled in **both** water passes. Both fluid materials now render two-sided — they have to agree, or the depth prime writes no depth at the underside and the double-blend that ADR 0007 eliminated comes straight back for anyone looking up through water.
- Stopped rippling water you are nowhere near. From an elevated vantage the whole lake surface rippled to the horizon, which reads as noise rather than as water. Wave amplitude and its shading normal now fade together between 28 and 90 metres — both, deliberately, because leaving the normal at full strength would keep a distant, now-flat surface glinting as though it were still moving. Honest note on the performance framing this came from: it saves shader work but no vertices, since the vertex is transformed either way. What it does buy is headroom for the near field, which is the direction the deferred wave work wants to go.
- Reworked creative flight so it matches swimming, and stopped it flying through walls. Flight was a plain MonoBehaviour writing `transform.position +=` directly, bypassing the locomotion mediator and the CharacterController entirely — so it had **no collision** and passed straight through terrain. It also moved only along the dominant hand's aim while jump was held, and disabled the move provider outright, so the stick did nothing at all while flying. It is now a locomotion provider like swimming: stick for horizontal through the existing move provider (so every comfort setting still applies), jump/A to rise, crouch/B to descend, sprint multiplies both, and vertical motion routes through the constrained body manipulator so it inherits collision and the live capsule height. One deliberate difference from swimming — with no input, flight **hovers**; swimming's resting state is sinking.
- Let swimmers climb out at low banks. Reaching the shore did not get you out: the swim state ends the moment the body sample reads dry, and that sample sits about a metre above the capsule base, so control was handed back while the player's feet were still below the bank and gravity pulled them straight back in. Nothing rescued it — step offset is a fraction of a metre, step assist needs grounding a treading player never has, and jump is disabled while swimming. The assist lifts onto a bank level with the water or one block above it, fires only while you are actively pushing toward the bank, and is bounded so the largest possible lift is two blocks. New **Climb Out At Low Banks** comfort toggle, on by default. Reverses a decision in [ADR 0008](docs/adr/0008-swim-locomotion.md); the amendment there records why.
- Gave every player the same warm hands, lit by the world they are standing in. In a sealed pitch-black cave the hands stayed brightly lit with visible directional shading while every wall around them rendered correctly black — because "sealed rooms are black" is a property of one shader plus baked vertex colour, not of the scene lighting, so any lit renderer not on that shader ignores caves completely. The hands were the only offender. Their albedo is now scaled by the same voxel light the world uses, sampled at each hand, which keeps the lit material's shading while still driving them dark in an enclosed space. Also collapsed an owner/remote colour split that disambiguated nothing — your own hands are always the pair attached to your view — and removed the blue that the local half used.

- Made lightning something you actually see. Strikes used to be drawn uniformly from the whole world and then *rejected* within 8 blocks of the player, so essentially every strike in the game happened somewhere nobody was looking — and what looked like a flash was four fog-wisp particles 8 cm across at 27% opacity, 8–16 m overhead, subtending about 0.4°. There was no sky flash at all, and the "ambient" flash near the player fired every 6–14 s with no strike behind it. Strikes are now biased into a ring 10–96 blocks around a player, **uniform in radius** so consecutive bolts genuinely differ in distance — some close enough to fill the view, some distant silhouettes on the horizon (area-uniform sampling was rejected: it piles strikes against the far edge where storm fog washes them out, which is close to the original problem). The inner radius sits just outside the existing 8-block comfort exclusion, so that exclusion is an invariant of the draw rather than a filter applied after it. Storms also stopped being uniform: a flat 35% roll every 10 seconds is replaced by a per-storm character (12%–70% peak) shaped by a build-peak-taper arc, both derived from state already in the environment snapshot, so this costs no extra network traffic and every peer computes the same storm. Placement is deliberately no longer reproducible from the seed alone — the anchor is a live head position — and that trade is recorded in [ADR 0009](docs/adr/0009-lightning-presentation.md) rather than left to be found as a regression.
- Gave lightning an actual bolt: a procedural ribbon mesh with three forks, a white-hot core falling to a blue edge, its foot landing exactly on the block it scorches. Three approaches were rendered at 12/45/90 blocks at Quest 3 angular scale before choosing; a stretched point-filtered sprite visibly stair-steps over tens of blocks, and — more decisively — any single tall billboard reads unmistakably as a **flat card in stereo**, swimming as the head translates, which is fatal for the one effect the player is meant to stop and look at. Soft edges come from a 64×1 alpha ramp generated in C# and sampled across the ribbon's width rather than from stacked layers, so there is no new art asset, no atlas entry, and the whole bolt — main channel, forks and impact glow — is one mesh and one draw. Billboarding is yaw only, because a full look-at rotation tilts the bolt when the player looks up and gives away the card. Lightning stays atmospheric: it scorches meadow turf and burns away leafmoss, and does no damage to anything.
- Added the sky flash, folded into the day/night lighting cycle rather than bolted onto it — that controller rewrites sun and ambient every `LateUpdate`, so anything poking a light from outside is erased within a frame. It modulates **ambient and never the sun**: at night the sun sits below the shadow-casting intensity floor, so raising it for a flash would flip the entire shadow pass on and off for two frames — a full shadow-caster sweep over every loaded chunk, with every shadow in the scene snapping in and out (there is a PlayMode test holding the sun's shadow mode constant across the whole flash at night). Its strength falls off quadratically with the strike's distance and reaches *exactly* zero at the ring's outer edge, so a close bolt washes out the sky and one on the horizon gives no flash at all — the term is re-added every frame, so a residual would bleed into ambient permanently. One flash at a time with a re-trigger gap, so two close strikes cannot compound into a strobe, and Reduced Flash suppresses both the bolt and the flash.
- Made thunder tell you how far away the strike was. It used to play the near clip immediately at full volume however distant the strike was, and the ambient rumble picked near-vs-far on a coin flip — no distance was computed for thunder anywhere in the codebase. Thunder is now delayed by `distance / 34` (0.3 s at the ring's inner edge, 2.8 s at its outer edge), attenuated with distance, and picks the near or far clip by distance. The divisor is deliberately about ten times slower than the real speed of sound: honest propagation over a 96-block ring peaks at 0.28 s, which nobody perceives as a delay, while the exaggerated figure makes the gap between seeing and hearing the single strongest distance cue in the game. Thunder plays 2D rather than positionally, because the positional path routes through a shared round-robin source pool that moves whichever source it picks — cutting off a clip still ringing — and would apply Unity's own rolloff on top of the distance curve, attenuating twice. The distance volume folds in beneath master volume, the weather bus and Mute All rather than around them. Thunder is queued before the Reduced Flash gate: that setting suppresses the visuals, not the storm. The clips themselves are still placeholders. The ruleset conflict between `/34` and `/343` in the two documents is resolved in favour of `/34`, with the reason recorded so it is not "corrected" later.
- Fixed every VFX cue's colour being silently discarded. The shared particle material was built as `URP/Unlit`, whose vertex input declares only position and UV — there is no `COLOR` semantic — while the pool writes each cue's tint into the particle vertex-colour stream. So block-break dust, sparks, embers, rain splash, snowflakes and fog wisps have all been rendering as flat white times their sprite since the effects landed, not just lightning's. The material now uses the URP particle shader, which consumes vertex colour. Lightning's flash also had no tint entry at all and fell through to a dull tan default — invisible while tint was being discarded, and obviously wrong the moment it started working.

- Made water see-through, lit, and moving. Fluids now render from a second, transparent material built from the same authored atlas and a `_BLOCKIVERSE_WATER` variant of the one voxel shader (a separate shader file would have been stripped from the Android player, since these materials are runtime clones nothing references as an asset), so a lake reads as water with the seabed visible under it rather than the solid blue floor the player has been sinking through since the fluid physics layer landed. The surface animates from a world-space wave that is continuous across chunk borders with no per-chunk uniform, and its lighting normal is rebuilt from the wave derivative — without that the whole animated surface stays lit as one rigid sliding sheet. The highlight is taken off that same band-limited wave normal rather than an independent sparkle sine, which would alias past ~20 m and alias *differently* in each eye: binocular rivalry, invisible in the flat game view and a comfort defect in the headset. Water keeps the full terrain lighting solve, so a torch-lit pool and a self-glowing emberflow still read correctly; the surface mask and fluid family ride a fluid-only second UV channel because vertex colour is already fully spent on sky exposure, emitter reach, and self emission. The wave only ever dips *below* the voxel face plane and only on emitted `+Y` faces, so no shoreline crack is expressible — including around a block placed on a lake, under a sapling, or where two fluid families meet — and fluid mesh bounds are padded downward so troughs cannot be frustum-culled and pop at the edge of vision. Geometry never moves on the CPU: colliders, buoyancy, and every gameplay query still read voxel data, so determinism and the save schema are untouched.
- Added swimming. Submerging the body hands vertical motion to a swim provider: hold the jump input to rise, hold crouch to descend, let go to sink. **Sinking is the default** — water should read as something you work against rather than a floor you bob on, so the surface is not a resting state and treading water is an active act. Because that is unrequested vertical motion, the escape hatch is first-class rather than buried: the Comfort menu's new **Sink When Not Swimming** switches it off for exact neutral buoyancy (with no input the app moves the player vertically by zero, so loading a save submerged, respawning underwater, or a fluid flowing into your cell produce no motion at all), alongside a **Swim Speed** slider and a **Vignette While Sinking** toggle that engages the tunneling vignette during passive descent. The descent is a velocity target reached by MoveTowards, never a spring, so it cannot overshoot, bob, or accumulate into a fall. Wading is deliberately not swimming: feet in fluid with a dry body keeps gravity on, so every puddle and the one-block shore step stays walkable. Swim-up reads the jump *action* rather than the jump provider, because jump is gated by locomotion mode — a Teleport-mode player who ended up submerged could otherwise swim down (crouch is not mode-gated) and not up while passive sink pulled them deeper, an inescapable underwater state in the *comfort* locomotion mode; swim-down reuses crouch, whose capsule shrink and camera drop are suppressed underwater. Gravity is suppressed with a forced-off lock **and** explicit registration in the gravity provider's controller list, because that list auto-populates only once from components already present — a provider added later is never consulted and the player sinks at falling speed with nothing to show why. Emberflow goes through the same path, thicker in every direction: it sinks you more slowly but it does sink you, and it still does not break a fall. Nothing replicates and the save schema is untouched: submersion is a pure function of the synced world blocks and the player's own position. Recorded in [ADR 0008](docs/adr/0008-swim-locomotion.md).
- Made water blend exactly once per pixel from every angle. `ZWrite` alone never made transparent blending order-independent — it decides which fragments survive, not how many blend, so whether a patch of water carried one layer of tint or two depended on voxel submission order, and the density visibly changed as the player walked around a lake. Water now renders as two materials on the one fluid renderer: a depth-only prime a queue earlier (`ColorMask 0`, `ZWrite On`), then the blended shading pass with `ZWrite` off. The prime claims each pixel for the nearest water fragment anywhere in the scene, so a far wall seen through a near surface — or another chunk's surface behind this one — is rejected before it can blend, which also removes per-chunk sort flips as the head turns. Ordering comes from the two materials' render queues rather than from URP's internal shader-tag order; both passes displace through the same shared helper and the prime carries the same water keyword, so it writes depth at the displaced height rather than the flat one; and the prime is nudged one depth unit away so the shading pass can use `ZTest LEqual` instead of an exact-equality test that would be at the mercy of the compiler's float scheduling. Terrain switches the prime pass off outright, so no chunk pays for a pass it does not want. Accepted trade: water now occludes *transparent* objects behind it (a particle effect behind a surface is rejected rather than tinted); opaque geometry is unaffected, so the seabed still reads through the water.
- Added the underwater view: submerging the head cross-fades exponential-squared fog and swaps the camera clear off the skybox over a quarter second, per fluid family (freshwater, brine, and a near-opaque hot emberflow), and restores both on surfacing. Fog is forced on while submerged regardless of weather — clear weather turns fog off entirely, which is exactly when swimming through perfectly clear water would look wrong — and applies even when the lighting cycle has no world clock or sun, a real state the controller early-returns on. Deliberately fog and camera clear only, with no camera-attached tint quad: every routed menu is a world-space canvas rendered by the same camera, so a near-clip quad would tint the pause and quit routes at emberflow's density and take the escape hatch away from the player in exactly the situation hurting them. Canvas UI does not consume fog, so menus and the survival HUD stay legible underwater. Losing the world while submerged (New World, Load, Return to Title) clears the view in the same frame rather than fading, since `Boot.unity` never unloads and nothing else would reset it. Recorded in [ADR 0007](docs/adr/0007-water-surface-rendering.md).
- Fixed late join breaking on any world that had actually been played. The whole changed-block set went out as one message, and Unity Transport sizes its fragmentation stage from `MaxPayloadSize` (6 KB by default), so past roughly 380 changed blocks the message was simply never delivered — the joining client sat forever with no world and every interaction rejected as "waiting for the host snapshot". Fluid flow, crop growth and snow settle all count as changed blocks, so a hosted world crossed that line within minutes even with no building. The snapshot is now a header plus bounded batches of 200 blocks (~3.2 KB each), assembled on the client only once world generation **and** every batch have landed — finalizing on generation alone would apply a partial delta set and leave the client quietly diverged. Regression-tested with a 900-changed-block world, which the old path could not sync at all.
- Added client recovery for a world that has drifted from the host. A buffered out-of-order delta, a run of unanswered requests, or a snapshot that stops mid-transfer now escalates to a `ResyncRequest`, and the host answers with a fresh world snapshot under a much tighter rate limit than edits (2 per 10 s per client).
